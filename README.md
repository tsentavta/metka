# metka — веб-терминал LoRa-маяка

Веб-терминал для маяка на STM32 с LoRa-радиомодулем. Маяк подключается по USB как виртуальный COM-порт («STM32 Virtual COM Port», VID `0483`, PID `5740`). Терминал — один файл [`web/terminal.html`](web/terminal.html): без сервера, без сборки и без установки.

**Онлайн:** https://tsentavta.github.io/metka/ (GitHub Pages)

## Запуск

1. Откройте ссылку выше или локальный файл `web/terminal.html` в **Google Chrome** или **Microsoft Edge**. Браузер должен поддерживать Web Serial.
2. Нажмите «Подключить» и выберите «STM32 Virtual COM Port».
3. Порт не должен быть занят другой программой.

### Fedora / Linux

Устройство появляется как `/dev/ttyACM*`. Нужны:

- права на порт: добавьте пользователя в группу `dialout` и войдите в систему заново;

  ```bash
  sudo usermod -aG dialout $USER
  ```

- запрет для ModemManager: иначе он считает порт модемом и шлёт в него AT-команды;

  ```bash
  echo 'ATTRS{idVendor}=="0483", ATTRS{idProduct}=="5740", ENV{ID_MM_DEVICE_IGNORE}="1"' | sudo tee /etc/udev/rules.d/99-metka.rules
  ```

  ```bash
  sudo udevadm control --reload-rules && sudo udevadm trigger
  ```

## Возможности

- Кнопки `GET`, `STATON` и `STATOFF`. Перед `STATOFF` терминал спрашивает подтверждение, а после `STATON` и `STATOFF` сам отправляет `GET`.
- Строка ввода любой команды. Окончание строки выбирается из списка: CR+LF (по умолчанию), CR, LF или без окончания. История команд листается стрелками ↑/↓.
- Лог с отметками времени. Ответ `OK!` выделен зелёным, `ERR0R` — красным. Лог можно сохранить в `.txt`.
- Таблица настроек устройства из ответа `GET`.
- Телеметрия: координаты, высота, скорость, курс, вертикальная скорость. Трек рисуется на схеме, рядом график высоты. Трек выгружается в CSV.

## Протокол (установлено опытным путём)

ASCII, 115200 8N1. Скорость на виртуальном порту роли не играет.

- **Команда** заканчивается на CR (`\r`). LF устройство пропускает, поэтому CR+LF тоже работает.
- **Ответ** — строки `КЛЮЧ=значение`, каждая заканчивается на `\r\n` и байт `0x00`. В конце идёт `OK!\n\r`.
- **Ошибка**: `ERR0R\n\r`. В слове цифра ноль вместо буквы O. Так устройство отвечает на любую неизвестную команду, включая пустую строку.

| Команда | Действие |
|---|---|
| `GET` | Прочитать настройки |
| `STATON` | Включить передатчик (`Stat=ON`) |
| `STATOFF` | Выключить передатчик (`Stat=OFF`). Внимание: с двумя F. `STATOF` даёт `ERR0R` |
| `FREQ=<Гц>` | Задать частоту, например `FREQ=866000000`. Работает не во всех прошивках, см. ниже |

### Поля ответа `GET`

| Поле | Пример | Значение (предположительно) |
|---|---|---|
| `ID` | `003437936` | Номер устройства |
| `FREQ` | `866000000` | Частота, Гц |
| `ModeSF` | `05` | LoRa spreading factor (SF5) |
| `Bandwidth` | `125` | Полоса, кГц |
| `Coding` | `01` | Coding rate: 4/(4+N) |
| `Power` | `22` | Мощность, дБм |
| `Stat` | `ON ` / `OFF` | Передатчик включён или выключен |
| `Preambule len` | `0010` | Длина преамбулы |
| `Time`, `Time to start`, `Time to landing`, `Time to undocking` | `010000` | Таймеры в формате ччммсс |
| `Logic` | `0` / `1` | Режим логики (см. ниже) |
| `Over`, `Fall` | `900`, `001` | Есть только в новой прошивке, назначение неизвестно |

### Телеметрия

Устройство само присылает строку примерно раз в 11 секунд:

```
<internal>Lt=DD.DDDDDD;Lg=DDD.DDDDDD;t=чч.мм.сс;h=ВВВВ.В;\r\n\0
```

Здесь `Lt` и `Lg` — широта и долгота в градусах, `t` — время (похоже, UTC), `h` — высота в метрах.

### Различия прошивок

Встречались две версии:

| | Старая (`Logic=0`) | Новая (`Logic=1`, есть `Over` и `Fall`) |
|---|---|---|
| `FREQ=<Гц>` | `OK!`, частота меняется | `ERR0R` |
| `STATON` | `OK!`, `Stat=ON` | `OK!`, но `Stat` остаётся `OFF` |
| Телеметрия `<internal>` | есть | не приходит |

Похоже, при `Logic=1` передатчиком управляет автоматика полёта (таймеры и пороги), а не ручная команда. Это не подтверждено документацией.
